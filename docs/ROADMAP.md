# 路线与待办

这份文档记录 2026-10-13 起的一轮改版（1.6.0）：手机页面改为底部四个栏目，新增“协作”（交接对话、同时提问、接力、定时提问）和“我的”（工作统计）。每一项写明现状、涉及的文件和验收办法，接手的人按“状态”一栏继续。规则见根目录 `AGENTS.md`，三方接口见 `docs/PROTOCOL.md` 的“The owner's work”。

## 界面结构

主界面是电脑端提供的内嵌页面 `web/index.html`（只连一台电脑时，App 打开后直接进入这一页；连了多台电脑时先进原生的工作台 `android/.../Workbench.java`，点进某台电脑后是这一页）。底部栏目做在内嵌页面里：

| 栏目 | 内容 | 代码 |
| --- | --- | --- |
| 任务 | 等你确认、置顶、正在运行、已打开、最近；搜索和筛选；右上角新建任务 | `web/app.js` |
| 项目 | 项目列表、进入项目、添加项目 | `web/app.js` |
| 协作 | 交接对话、同时提问、接力、定时提问 | `web/together.js` |
| 我的 | 工作统计、电脑端版本和工具；右上角进入设置 | `web/me.js` |

“终端 / 应用”没有拆成两个栏目，仍是“任务”和“项目”里的筛选项：它们是同一批对话的两种来源，拆开会把“哪些在等我”分散到两处。

新栏目以模块加入：`app.js` 把页面的公共部分交给 `window.RemoteCliPage`（请求、弹层、对话列表、判断发送方式等），每个栏目的模块用 `RemoteCliPage.view(名称, { open, draw })` 登记自己，只管自己那一块页面。再加栏目时照此办理，并在 `index.html` 的 `#tabs` 里加一个按钮。

## 未完成

| 项目 | 现状 | 怎样继续 |
| --- | --- | --- |
| 手机上的验收 | 这里没有真机和模拟器，页面只在无界面的 Chrome 里按手机尺寸检查过 | 在手机上看：底栏与系统导航键的间距、键盘弹出时的表现、各外观下的图表、日期和时间选择器 |
| 多台电脑时的原生工作台 | `Workbench.java` 没有底栏；进入某台电脑后才有四个栏目 | 需要决定原生工作台是否也要“协作”“我的”（跨电脑汇总统计），改完要在手机上看 |
| 交接和接力文字在真实工具上的表现 | 两段文字各在真实的 Claude Code 上作为用户消息试过一次（小模型，临时文件夹），都被当作用户的要求处理；Codex 上没有试过，经钩子送达的情形也没有单独试 | 在临时文件夹里对 Codex 各试几次，并在执行中的对话上试一次经钩子送达，看工具是否照着做 |
| Linux 上的接力 | 没有：Linux 电脑端不装工具的钩子，不知道对话何时停下 | 可以按终端输出静止来判断（中转里 `_phase` 的做法），需要把这个判断挪到电脑端 |
| 统计的增量读取 | 记录文件有变化时整个重读，结果只缓存在内存 | 记下每个文件读到的位置，只读新增部分；汇总落盘 |

## 后续想法

按“省时间”排序，都还没有做：

1. **交接到新对话。** 交接时直接在目标工具里新开终端并把交接说明作为第一句话（现在只能选已经开着的对话）。`start` 操作已经能带首句的话就很近了。
2. **定时提问的新对话目标。** 到点在某个项目里新开一个 Claude Code 或 Codex 终端并发出第一句话。
3. **同时提问后的并排对比。** 把几段对话对同一问题的回答放在一页里对照。
4. **快捷指令。** 常用的话存成按钮（“继续”“运行测试并修复”“总结一下进度”），在对话窗口一点就发。
5. **每日简报。** 每天固定时间把各对话做了什么整理成一页，配合任务提醒推送。
6. **超时提醒。** 一段对话连续执行超过设定时间、或等确认超过设定时间时提醒。
7. **用量预警。** 当天 token 用量超过设定值时在“我的”和通知里提示。
8. **接力的条件。** 只有回答里出现某个词（例如“测试未通过”）时才触发，或交给不同的对话。
