# 手机与电脑协同控制计划

目标是让同一个任务在手机与电脑之间连续使用，打开手机不改变电脑正在运行的程序，返回或断网不结束任务。完整控制以同一个运行实例为基础；恢复历史与创建副本都不作为实时同步。

## 已确认的问题

- Remote AI 自己创建的终端已经支持两个客户端连接同一进程。电脑已有的外部对话则通过扫描记录、钩子和工具消息入口接入，两者的控制能力不同。
- `can_takeover` 表示能否结束独立 CLI 进程，不能代表能否停止某次生成、关闭桌面应用中的一个标签或安全释放共享后台中的单段对话。
- Android 工作台此前没有读取 `can_takeover`，也没有调用已有的 `session_end`，导致浏览器内可以结束的独立 CLI，在 App 工作台没有对应操作。
- 手机发送接口可能只接受了排队消息；客户端没有区分排队、工具接收和记录中已出现。按“出现了其它用户消息”删除本地待发送项会把电脑端的输入误当作手机消息送达。
- 外部会话的“接管”会结束原进程再恢复历史。副本则产生独立对话，不能满足两端继续同一任务的要求。

## 交互约定

| 操作 | 用户看到的效果 | 实现边界 |
| --- | --- | --- |
| 打开 / 返回 | 查看或离开同一任务，电脑继续运行 | 只连接或断开视图 |
| 发送消息 | 明确显示发送中、已排队、工具已接收；失败保留输入 | 排队不宣称执行完成，不自动重发结果未知的消息 |
| 停止当前执行 | 终止这一轮，保留对话和原应用 | 仅在连接当前运行实例且适配器支持时提供 |
| 结束会话 | 结束所选运行实例，保留已保存记录 | 只允许已核实的独立进程，或应用提供的会话级关闭接口 |
| 隐藏 / 归档 | 改变列表展示或历史归档 | 不冒充停止或结束 |
| 接管到共享终端 | 结束外部 CLI 后在 Remote AI 终端恢复；手机和电脑随后连接同一个终端 | 单独确认中断后果；不用于共享应用进程 |
| 创建副本 | 新任务继承已有历史，原任务继续 | 明示后续不相互同步，放在次级菜单 |

常用路径为“打开任务 → 输入 → 查看执行 → 返回”。接管和副本不放在发送失败后的默认补救位置。沿用现有颜色、字号和页面结构，优先保证长对话的阅读空间、固定输入区和手机触控；操作不可用时说明原因，不用消失的输入框或必然失败的按钮代替解释。

## 外部应用的准入条件

适配器必须连接正在服务目标对话的原实例。扫描历史文件只能证明可读；消息队列只能证明可提交；独立 CLI 的进程归属只能证明可结束该进程。三者均不能推出对桌面应用的完整控制能力。

尚未核实的应用级控制不承诺可用。优先验证官方会话、执行中断、审批和关闭接口；若原应用不开放这些接口，再评估用户可见的窗口控制方案及其焦点冲突、权限和多窗口定位。不得删除写入锁、修改对话数据库、结束共享后台或启动第二个写入者来制造同步效果。

## 首个应用适配器：Codex Windows

本轮限定为原应用的项目和新对话草稿入口。Codex 26.1007.2314.0 的桌面入口接受 `codex://threads/new?path=…&prompt=…`，由应用自身选中或创建项目并显示输入界面；它没有提供本次调用的完成回执。CLI 的独立 `app-server` 和共享 daemon 均不能据此视作 Windows 桌面应用的当前后台。因此实现只报告 `handed_off`，不报告对话已创建或消息已发送。

| 工作项 | 唯一输入 / 依赖 | 输出 | 状态与验收证据 |
| --- | --- | --- | --- |
| 应用入口与能力 | 本机桌面包的路由和项目处理代码；已安装包登记 | `DesktopAdapters.cs`，独立适配器接口、已安装版本检测、限定路径和草稿参数 | 已实现；专项检查通过，真实应用可探测，未以进程启动回执充当原生窗口验证 |
| 异步执行和重复请求 | `RemoteCliAgent.cs`、电脑允许的项目目录 | 后台执行，操作前写入保留记录，重复请求读取结果；中断后报告未知 | 已验证；并发、重启、失败回执、损坏记录、目录权限、远控关闭及非阻塞测试 |

| 协议和兼容性 | `relay.py` 的操作队列与原有鉴权路由 | `app_open` 和 `codex-desktop-open`；旧端不显示有效操作入口 | 已验证；64 项中转测试、Windows 构建、共享终端历史测试、Android Java 编译及聚合测试 |

界面沿用现有浅色/深色主题、底部表单和主要按钮，不增加新的导航层。表单保留草稿，提交期间禁止重复点击；断线后的查询复用操作编号。返回只离开表单，不撤回已交给电脑的操作。截图与几何报告在本地 `.build/desktop-ui/`。
